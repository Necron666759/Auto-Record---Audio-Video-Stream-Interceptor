====================================================================
 Auto Record - Audio/Video Stream Interceptor
 Инструкция пользователя (Русский)
====================================================================

О ПРОГРАММЕ
--------------------------------------------------------------------
Программа автоматически записывает воспроизведение трека на Suno
(звук) или видео/аудио на YouTube через отдельный, изолированный
экземпляр Firefox: запускает браузер, открывает страницу, следит за
плеером и записывает звук (а для YouTube — по желанию и видео),
изолируя запись именно от этого браузера, а не от всей системы.

Управление — через графический интерфейс (recorder_gui.py), но при
желании оба сценария (Suno и YouTube) можно запускать и напрямую из
терминала, как обычные Python-скрипты со своими флагами (--help
покажет полный список).

Начиная с этой версии программа умеет сама, без предварительно
открытого основного Firefox, поднимать браузер по кнопке
"Запустить запись": при первом успешном запуске (когда основной
Firefox всё же был открыт хотя бы раз) она сохраняет отдельную
постоянную копию его профиля и путь к firefox-bin в
~/.cache/auto_record_suno/, и на всех следующих запусках использует
эту копию напрямую. Если логин/сессия в этой копии протухнет —
в GUI есть кнопка "Сбросить кэш профиля Firefox" (или флаг
--reset-firefox-cache в консольных скриптах), после чего следующий
запуск снова возьмёт свежий профиль из открытого основного Firefox.


СОДЕРЖИМОЕ ПОСТАВКИ
--------------------------------------------------------------------
  recorder_gui.py           - графический интерфейс (точка входа)
  auto_record_suno.py       - логика записи Suno + вся общая логика
                               работы с Firefox/звуком (используется
                               и вторым сценарием тоже)
  auto_record_youtube.py    - логика записи YouTube (аудио/видео)
  screen_capture.py         - захват экрана для видео (X11/Wayland)
  format_options.py         - список форматов/контейнеров
  encode_helpers.py         - обвязка над ffmpeg
  gui_profiles.py           - сохранённые профили настроек GUI
  i18n.py                   - локализация интерфейса (RU/EN)

  AppDir/, build-appimage.sh - заготовка для сборки AppImage
                               (см. раздел "AppImage" ниже)


ТРЕБОВАНИЯ (что должно быть установлено в системе)
--------------------------------------------------------------------
Программа НЕ требует установки через pip — только стандартная
библиотека Python. Но ей нужны системные пакеты и программы:

  1. Python 3.9+ с модулем tkinter (для графического интерфейса)
  2. ffmpeg (и ffprobe — обычно идёт в одном пакете с ffmpeg)
  3. Утилиты PulseAudio: pactl и parec
     (на системах с PipeWire их предоставляет пакет pipewire-pulse -
     это совместимая замена, ничего доустанавливать отдельно не надо,
     если PipeWire уже настроен как замена PulseAudio)
  4. Разделяемая библиотека libpulse (используется напрямую через
     ctypes для более надёжного мониторинга звукового устройства)
  5. Настоящий (НЕ Snap и НЕ Flatpak) Firefox - программе нужен
     реальный процесс firefox-bin, который ищется через /proc.
     Snap/Flatpak-сборки Firefox работают в отдельном пространстве
     имён и/или используют другую структуру бинарников - программа
     может не найти нужный процесс. Firefox НЕ ставится автоматически
     ни списками пакетов ниже, ни скриптом build-appimage.sh -
     убедитесь, что у вас уже есть подходящая установка Firefox.
  6. wf-recorder - ТОЛЬКО если планируется записывать ВИДЕО с
     YouTube в сессии Wayland (X11 в этом не нуждается: там
     используется штатный ffmpeg -f x11grab). ВАЖНО: wf-recorder
     работает только под wlroots-композиторами (Sway, Hyprland и
     т.п.). Под GNOME/KDE на Wayland видео-запись не заработает -
     либо используйте запись только звука, либо переключитесь на
     сессию X11/Xorg при входе в систему.
  7. FUSE (libfuse2/fuse2) - нужен, чтобы вообще запускать AppImage
     на некоторых свежих дистрибутивах (см. ниже).

geckodriver отдельно ставить НЕ нужно - при первом запуске скрипт
сам скачивает нужную версию с GitHub Releases в
~/.cache/auto_record_suno/geckodriver и переиспользует её дальше
(для этого разового скачивания нужен интернет).


ПАКЕТЫ ПО ДИСТРИБУТИВАМ
--------------------------------------------------------------------

Debian / Ubuntu (apt):
  sudo apt update
  sudo apt install python3 python3-tk ffmpeg pulseaudio-utils \
      libpulse0 libfuse2 wf-recorder

  Примечания:
   - На Ubuntu 24.04+ пакет может называться libfuse2t64 вместо
     libfuse2 - apt сам предложит нужное имя.
   - wf-recorder нужен только для видео на Wayland (см. пункт 6 выше).
   - Firefox этим списком НЕ ставится - см. пункт 5 выше о том,
     какая именно сборка Firefox нужна программе.

Fedora (dnf):
  sudo dnf install python3 python3-tkinter ffmpeg pulseaudio-utils \
      fuse fuse-libs wf-recorder

  Примечание: если системный ffmpeg собран без mp3/aac (что
  случается без включённого репозитория RPM Fusion), программа
  попробует сама скачать статическую сборку ffmpeg с нужными
  кодеками - для этого разового скачивания нужен интернет.

Arch Linux / Manjaro (pacman):
  sudo pacman -S python tk ffmpeg libpulse pulseaudio \
      fuse2 wf-recorder
  (если используется PipeWire вместо PulseAudio:
   sudo pacman -S pipewire-pulse - обеспечит pactl/parec)

openSUSE (zypper):
  sudo zypper install python3 python3-tk ffmpeg pulseaudio-utils \
      libpulse0 fuse wf-recorder


ЗАПУСК БЕЗ APPIMAGE (напрямую)
--------------------------------------------------------------------
  python3 recorder_gui.py

Все файлы .py должны лежать в одной папке (они импортируют друг
друга по относительному пути рядом со скриптом).


СБОРКА И ЗАПУСК APPIMAGE
--------------------------------------------------------------------
В комплекте поставки есть готовая папка AppDir/ (уже содержит все
.py-файлы, AppRun-скрипт запуска, .desktop-файл и иконку) и скрипт
build-appimage.sh, который делает две вещи одной командой:

  1) определяет ваш дистрибутив (Debian, Ubuntu, Fedora, RHEL/CentOS/
     Alma/Rocky, Arch/Manjaro, openSUSE - и их производные) и
     доустанавливает через apt/dnf/pacman/zypper всё, чего не хватает
     для работы программы (python3-tk, ffmpeg, pulseaudio-utils,
     libpulse, fuse и т.д. - конкретно для вашей системы; Firefox
     этим скриптом НЕ ставится - см. пункт 5 выше);
  2) скачивает appimagetool и собирает готовый файл
     Recorder-x86_64.AppImage.

  chmod +x build-appimage.sh
  ./build-appimage.sh

Перед установкой пакетов скрипт покажет список того, чего не хватает,
и спросит подтверждение (нужен sudo, если вы не root). Полезные флаги:

  ./build-appimage.sh --yes         не спрашивать подтверждения,
                                     сразу ставить пакеты и собирать
  ./build-appimage.sh --skip-deps   не трогать пакеты вообще, только
                                     собрать AppImage
  ./build-appimage.sh --deps-only   только проверить/поставить
                                     пакеты, AppImage не собирать
  ./build-appimage.sh --help        краткая справка по флагам

Если распознать дистрибутив не удалось, скрипт сам пропустит шаг
установки пакетов и предложит поставить их вручную по списку из этого
файла (см. раздел "ПАКЕТЫ ПО ДИСТРИБУТИВАМ" выше), а затем повторно
запустить со флагом --skip-deps, чтобы дособрать только AppImage.

Для установки пакетов и для сборки нужен интернет (appimagetool
скачивается один раз и кэшируется рядом со скриптом).

После сборки просто запустите:
  ./Recorder-x86_64.AppImage

ВАЖНО про AppImage: сам AppImage НЕ содержит внутри себя Python,
ffmpeg, Firefox и т.п. - он использует то, что уже установлено в
системе (см. разделы выше). Это осознанное решение: программа
напрямую работает с системным PulseAudio/PipeWire и системным
Firefox через /proc, и это невозможно "упаковать внутрь" AppImage -
эти вещи обязаны быть частью хост-системы. Если каких-то пакетов не
хватает, AppRun выведет понятное сообщение с названием пакета для
вашего дистрибутива, вместо непонятной ошибки Python.

Если при запуске AppImage система пишет "не удаётся выполнить
файл" или "permission denied" - убедитесь, что установлен FUSE
(см. раздел про требования выше) и что у файла выставлены права на
исполнение (chmod +x Recorder-x86_64.AppImage).


КЭШ ПРОФИЛЯ FIREFOX
--------------------------------------------------------------------
Расположение: ~/.cache/auto_record_suno/
  firefox_profile/            - постоянная копия профиля Firefox
  firefox_binary_path.txt     - запомненный путь к firefox-bin
  geckodriver/, ffmpeg/       - автоматически скачанные утилиты

Первый запуск записи должен пройти при открытом основном Firefox -
именно из него программа один раз возьмёт профиль и путь к
бинарнику. Все последующие запуски эти данные уже не требуют.

Если логин на Suno/YouTube в кэше протух (разлогинило) - нажмите в
GUI кнопку "Сбросить кэш профиля Firefox", откройте основной
Firefox, залогиньтесь там заново и запустите запись ещё раз - кэш
пересоздастся из свежего профиля.
