====================================================================
 Auto Record - Audio/Video Stream Interceptor
 Инструкция пользователя (Русский) — редакция для Windows 10/11
====================================================================

О ПРОГРАММЕ
--------------------------------------------------------------------
Программа автоматически записывает воспроизведение трека на Suno
(звук) или видео/аудио на YouTube через отдельный, изолированный
экземпляр Firefox: запускает браузер, открывает страницу, следит за
плеером и записывает звук (а для YouTube — по желанию и видео),
изолируя запись именно от этого браузера, а не от всей системы.

Управление — через графический интерфейс (recorder_gui.py), но при
желании оба сценария (Suno и YouTube) можно запускать и напрямую из
командной строки, как обычные Python-скрипты со своими флагами
(--help покажет полный список).

Программа сама, без предварительно открытого основного Firefox,
поднимает браузер по кнопке "Запустить запись": профиль берётся из
%APPDATA%\Mozilla\Firefox\profiles.ini, а путь к firefox.exe — из
реестра Windows (App Paths) или стандартных папок установки. При
первом успешном запуске сохраняется отдельная постоянная копия
профиля и путь к firefox.exe в %LOCALAPPDATA%\auto_record_suno\, и
на всех следующих запусках используется эта копия напрямую. Если
логин/сессия в этой копии протухнет — в GUI есть кнопка "Сбросить
кэш профиля Firefox" (или флаг --reset-firefox-cache в консольных
скриптах), после чего следующий запуск снова возьмёт свежий профиль
из основного Firefox (его достаточно один раз открыть и залогиниться).

Это Windows-редакция программы, портированная с Linux-версии.
Отличия от Linux по сути дела нет — интерфейс, набор контейнеров,
профили настроек и оба сценария (Suno и YouTube) те же самые.
Разница — только там, где этого требует сама операционная система
(изоляция звука, захват экрана, поиск Firefox и т.п.); подробности
см. в разделе "ЧТО ИЗМЕНИЛОСЬ ТЕХНИЧЕСКИ" ниже. Также в Windows-
версии есть чекбокс "Аварийный режим" (запись всего звука системы
без изоляции по Firefox), которого нет в Linux-версии — см. раздел
"ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ".

ТРЕБОВАНИЯ (что должно быть установлено в системе)
--------------------------------------------------------------------
Программа НЕ требует установки через pip — только стандартная
библиотека Python. Но ей нужны:

  1. Windows 10 версии 2004 (сборка 19041) или новее, либо Windows 11.
     Это требование именно версии Windows, а не программы: изоляция
     звука по процессу (WASAPI Process Loopback Capture) появилась
     только в этой версии. На более старых системах Process Loopback
     недоступен — используйте аварийный режим (см. "ИЗВЕСТНЫЕ
     ОГРАНИЧЕНИЯ" ниже), либо обновите Windows.
  2. Python 3.9+ с модулем tkinter (для графического интерфейса).
     Обычный установщик с python.org ставит tkinter вместе с Python -
     ничего доустанавливать отдельно не требуется. Если запускаете
     собранный .exe/.msi/Setup.exe (см. "СБОРКА ДИСТРИБУТИВА") — сам
     Python на компьютере вообще не нужен, он уже внутри.
  3. Настоящая (НЕ из Microsoft Store) установка Firefox. Программе
     нужен путь к firefox.exe, который она ищет через реестр Windows
     (App Paths) и стандартные папки установки — Store-версия Firefox
     (MSIX) использует другую схему установки и путь к бинарнику
     может не найтись. Обычный установщик с firefox.com/ru/ подходит.
  4. Свободное место на диске для автоматически скачиваемых
     ffmpeg и geckodriver (см. раздел "КУДА СОХРАНЯЮТСЯ СКАЧИВАЕМЫЕ
     ФАЙЛЫ" ниже) — как правило, до 150-200 МБ.

Ничего из перечисленного ниже ставить отдельно НЕ нужно —
программа скачивает и кэширует это сама при первом запуске (нужен
интернет только для этого разового скачивания):

  - geckodriver — с GitHub Releases (github.com/mozilla/geckodriver);
  - ffmpeg — готовая Windows-сборка с gyan.dev (build-essentials).
    Если системный ffmpeg уже есть в PATH и содержит нужные кодеки,
    используется он, а автозагрузка не выполняется.

В отличие от Linux-версии, здесь НЕ нужны: PulseAudio/PipeWire и его
утилиты pactl/parec (изоляция звука сделана через WASAPI, входит в
саму Windows), wf-recorder (захват видео — через ffmpeg gdigrab,
тоже не требует установки) и FUSE (концепция AppImage для Windows
не применяется — см. "СБОРКА ДИСТРИБУТИВА").

## Что изменилось технически (порт на Windows)

Исходная версия целиком построена на Linux-специфичных механизмах
(PulseAudio для изоляции звука конкретного приложения, `/proc` для
поиска процессов, x11grab/wf-recorder для захвата экрана). Ни того,
ни другого на Windows нет, поэтому:

- **Изоляция звука Firefox** делается через нативный Windows API
  **WASAPI Process Loopback Capture** (появился в Windows 10 2004+ /
  Windows 11) — тот же механизм, которым пользуется, например, захват
  звука конкретного приложения в OBS Studio. Реализация — `win_audio_loopback.py`.
- **Поиск/завершение процессов** — через `win_process.py`
  (ctypes + `CreateToolhelp32Snapshot`, вместо `/proc`).
- **Поиск профиля/бинарника Firefox упрощён**: программа больше не
  требует заранее открытого основного Firefox и не закрывает его —
  профиль берётся из `%APPDATA%\Mozilla\Firefox\profiles.ini`, бинарник —
  из реестра (`App Paths`) / стандартных папок установки / PATH. Firefox
  всегда запускается отдельным процессом с копией профиля.
- **Захват экрана для видео (YouTube)** — через `ffmpeg -f gdigrab`
  (`screen_capture.py`), вместо x11grab (X11) / wf-recorder (Wayland).
  На Windows нет выбора "сервера отображения" — gdigrab один на все случаи.
- **ffmpeg** при необходимости скачивается готовой Windows-сборкой с
  gyan.dev (вместо статической Linux-сборки johnvansickle.com — сам
  johnvansickle.com Windows-сборки не публикует).
- **Работа без окна консоли, диагностика звука, чекбокс "Аварийный
  режим"** — см. соответствующие разделы ниже; в Linux-версии этого
  нет либо не нужно по другим причинам (там есть терминал, а
  изоляция звука через PulseAudio не имеет "аварийного" режима —
  она либо есть, либо нет).

## Проверено на реальной Windows

Изоляция звука (WASAPI Process Loopback), захват видео (gdigrab) и весь
Windows-слой в целом опробованы на реальной Windows-машине — серьёзных проблем
в работе не выявлено. Файлы `win_audio_loopback.py`, `win_process.py` и
`screen_capture.py` изначально написаны по документированному поведению
WinAPI/WASAPI/GDI (структуры, GUID'ы и сигнатуры — из публичной документации
Microsoft и официального C++-сэмпла `ApplicationLoopback`), а затем
проверены на практике.

Если у вас на конкретной конфигурации что-то всё же пойдёт не так — заведите
Issue в репозитории на GitHub с логом из программы (кнопка "Проверить
звуковые устройства" / `--list-audio-devices` в описании ошибки очень
помогает) и версией Windows. Отдельно полезно для диагностики:
`python win_audio_loopback.py <PID_firefox> 5` — печатает журнал попыток
запуска захвата с кодами HRESULT. Как запасной вариант **без изоляции по
процессу** — флаг `--capture-mode device` в CLI, или чекбокс "Аварийный
режим" в GUI.

## Известные ограничения

- Process Loopback Capture требует Windows 10 версии 2004 (сборка
  19041) или новее, либо Windows 11. На более старых системах
  используйте `--capture-mode device`.
- `win_process.py::_wait_for_firefox_process` определяет "наш"
  firefox.exe как дочерний процесс запущенного geckodriver — это
  надёжно в обычных условиях, но теоретически может дать сбой на
  нестандартных сборках Firefox, которые перезапускают себя через
  промежуточный launcher-процесс.
- Автозагрузка ffmpeg ссылается на конкретный URL gyan.dev; если сборка
  переедет — обновите константу в `auto_record_suno.py::_download_static_ffmpeg_windows`
  или используйте `--no-auto-ffmpeg` со своим `ffmpeg.exe` в PATH.
- Захват экрана (gdigrab) пишет то, что физически отображается на
  экране — если плеер маленький, а видео нативно в 1080p/4K, в кадре
  всё равно будет размер плеера (см. предупреждение в шапке
  `auto_record_youtube.py`). Курсор мыши и окна поверх плеера тоже
  попадают в запись. DRM-защищённое видео gdigrab пишет чёрным.

## История правок, найденных при переносе на Windows

Ниже — хронология проблем, обнаруженных и исправленных в процессе разработки
и тестирования (полезно, если похожая ошибка встретится в логе снова):

1. **Аварийное завершение при нажатии "Остановить" (код выхода
   3221225786 / `STATUS_CONTROL_C_EXIT`).** Было устранено переходом
   на остановку через `STOP` в stdin воркера — см. раздел
   "Правки: диагностика звука и второе (консольное) окно" ниже,
   где описан итоговый (актуальный) механизм остановки.
2. **`WinError 3` при сохранении профиля Firefox в кэш** (путь вида
   `...\Firefox\1`). Баг парсинга `profiles.ini`: поле `Default` — это
   ПУТЬ только в секциях `[InstallXXXX]`; в секциях `[ProfileN]` это
   флаг `0`/`1`, путь — в отдельном поле `Path`. Исправлено.
3. **`'charmap' codec can't encode character...`** — консоль Windows
   по умолчанию пишет не в UTF-8, а в активную кодовую страницу; символ
   вне неё (например, в названии трека) ронял `print()` НАВСЕГДА на
   одном и том же месте. `stdout`/`stderr` теперь явно переключены в
   UTF-8 с `errors="replace"`.
4. Заодно портирован отсутствовавший в Windows-версии шаг **`atempo`**
   (компенсация скорости/тона при `--rate != 1.0`) и диагностическая
   сверка длительности записанного файла — это было в исходной Linux
   версии, но потерялось при первом переносе.

### Правки: «запись не происходит» (лог с 32 повторами «пропал интернет»)

1. **`[WinError -2147483634]` = `0x8000000E` (E_ILLEGAL_METHOD_CALL) при запуске
   захвата.** Обработчик завершения `ActivateAudioInterfaceAsync` обязан быть
   «agile» (отвечать на `QueryInterface(IAgileObject)`); реализация на
   `comtypes.COMObject` этого не делала. `win_audio_loopback.py` переписан на
   чистый ctypes (без `comtypes`): собственный COM-объект с IUnknown /
   IActivateAudioInterfaceCompletionHandler / IAgileObject, явные вызовы через
   vtable, HRESULT возвращается числом и превращается в `LoopbackCaptureError`
   с названием этапа и кодом.
2. **Сбой захвата выдавался за «пропал интернет».** `_looks_like_network_error`
   считал сетевой любую `OSError` (а её бросает и ctypes/WinAPI). Теперь ошибки
   захвата и WinAPI сетевыми не считаются; `HTTPError` от geckodriver — тоже.
3. **Бесконечный цикл без пауз.** После 3 подряд неудачных запусков захвата
   программа останавливается с понятным сообщением (код 2) и подсказкой про
   `--capture-mode device`.
4. **Формат записи — как в Linux: WAV 96 кГц / 24 бит (pcm_s24le).** Захват
   идёт на 96 кГц во float32 (родной формат движка Windows, без потерь), ffmpeg
   пишет WAV 96 кГц / 24 бит. Если система не принимает 96 кГц, перебираются
   запасные форматы (48 кГц float32, 44,1 кГц/16 бит из сэмпла Microsoft) —
   итоговый файл всё равно 96 кГц / 24 бит. FLAC снова сохраняет 96 кГц/24 бит
   (`-ar 96000`, как в Linux).
5. **PID Firefox берётся из `moz:processID`** (ответ geckodriver), а не как
   «первый firefox.exe-потомок» — это может быть недолговечный launcher.
6. **Тишина в паузах.** WASAPI loopback не присылает пакеты, когда нет звука;
   простои дописываются нулями по настенным часам (как непрерывный parec).
7. **Диагностика:** предупреждение, если записана одна тишина; выбранный формат
   и журнал попыток печатаются в лог.
8. **Лог приходил не по порядку** (stderr впереди stdout): PyInstaller-сборка
   игнорирует `PYTHONUNBUFFERED`. Теперь `stdout` переключается в
   построчную буферизацию.
9. Убрана зависимость `comtypes` (и `--collect-all comtypes` в сборке).

Если захват не запускается, выполните на Windows (во время воспроизведения
трека в Firefox) `python win_audio_loopback.py <PID_firefox> 5` — скрипт покажет
журнал попыток с кодами HRESULT.

### Правки: Firefox «резко закрывается», ошибки HTTP 500 / 404

Симптомы из логов: `Traceback ... HTTP Error 500: Internal Server Error` сразу
после запуска и/или бесконечная серия `ERROR при обработке трека: HTTP Error 404`
после закрытия браузера.

1. **Программа сама закрывала Firefox при сбое открытия страницы.** Ошибка
   `HTTP Error 500` при первом переходе на suno.com — это ответ geckodriver
   «Reached error page: about:neterror…» (нет сети / DNS / обрыв). Текст причины
   лежит в ТЕЛЕ ответа, а `urllib` показывал только «Internal Server Error», поэтому
   `navigate_with_retry` не узнавал сетевую ошибку, пробрасывал её наверх, и
   `finally: session.quit()` закрывал Firefox. Теперь тело ответа читается
   (`WebDriverError`), сетевая ошибка распознаётся, программа ждёт интернет и
   повторяет переход с нарастающей паузой — браузер не закрывается.
2. **Автоперезапуск Firefox.** Если браузер закрылся/упал/потерял сессию (в логе
   это `HTTP 500 … Failed to decode response from marionette`, затем `404 invalid
   session id` на каждую команду), программа больше не крутится вхолостую: она
   пишет отчёт (код выхода Firefox, есть ли файл-отчёт о падении, последние строки
   вывода geckodriver), сохраняет то, что успело записаться в текущем треке,
   перезапускает Firefox и снова открывает стартовую страницу. Дальше нужно
   нажать play. Лимит — 5 перезапусков подряд без единого сохранённого трека
   (потом код выхода 3). То же самое реализовано и для YouTube-воркера.
3. **`is_pid_alive` врал.** Пока geckodriver держит handle на завершившийся
   firefox.exe, `OpenProcess` продолжал успешно открываться, и закрывшийся Firefox
   считался «живым». Теперь проверяется код завершения процесса; добавлен
   `win_process.ProcessWatch` (handle на процесс + код выхода Firefox, заодно защита
   от убийства постороннего процесса при переиспользовании PID).
4. **stderr geckodriver не вычитывался** (`subprocess.PIPE` без чтения): когда
   буфер трубы заполнялся, geckodriver и Firefox блокировались на записи в лог.
   Теперь вывод вычитывается отдельным потоком (последние 200 строк хранятся для
   отчёта).
5. **Локальные запросы к geckodriver не идут через системный прокси** (VPN- и
   прокси-клиенты выставляют его в настройках Windows; urllib его подхватывал бы и
   для 127.0.0.1).
6. **`wait_for_internet` ограничен по времени** (180 с): проверка идёт из самой
   программы (1.1.1.1 / 8.8.8.8 / suno.com) и может ошибаться, если доступ к Suno
   идёт через VPN/прокси только в браузере — раньше программа могла зависнуть в
   ожидании навсегда.
7. Ошибки захвата звука после закрытия Firefox больше не засчитываются как
   «Windows слишком старая» (счётчик из 3 сбоев запуска захвата); простое
   ожидание нажатия play (10 минут) больше не логируется как ERROR.
8. В GUI добавлен блок **«Сервис»** под шапкой (Suno / YouTube — см. ниже).

### Правки: диагностика звука и второе (консольное) окно

**1. Кнопка «Проверить звуковые устройства» теперь работает** (раньше печатала
заглушку «не реализовано»). Реализация — `win_audio_devices.py`; то же самое
доступно из CLI: `python auto_record_suno.py --list-audio-devices` (и то же самое
для `auto_record_youtube.py`). Отчёт содержит:

- версию Windows и пригодность для Process Loopback (нужна сборка 19041+);
- устройства ВЫВОДА (Core Audio, чистый ctypes): название, тип (колонки / наушники /
  HDMI…), состояние (активно / отключено / не подключено), формат микшера Windows и
  пометку «ПО УМОЛЧАНИЮ» (консоль / мультимедиа / связь) — именно устройство по
  умолчанию слушает аварийный режим; устройства ВВОДА перечислены списком;
- РЕАЛЬНУЮ проверку запуска захвата теми же классами, что использует запись:
  изоляция по процессу (Process Loopback) и аварийный режим — с форматом или кодом
  ошибки HRESULT;
- итог с рекомендацией (включить «Аварийный режим», запустить службу Windows Audio,
  подключить устройство и т.п.).

Проверка запускается в фоновом потоке (окно не «замирает»), строки появляются в логе
по мере готовности, повторное нажатие во время проверки игнорируется, таймаут — 120 с.
Важно: проверяется, что захват *инициализируется*; идёт ли реально звук — отдельно:
`python win_audio_loopback.py <PID_firefox> 5`.

**2. Второе пустое окно (консоль) убрано.** Причина: exe собирался как консольное
приложение. Штатно скрыть консоль нельзя надёжно (`--hide-console` PyInstaller не
работает на Windows 11 с Windows Terminal), поэтому сборка теперь **windowed**
(`--noconsole` в `build-windows.sh`). Всё, что раньше держалось на консоли,
переделано (`win_stdio.py`):

- **Остановка.** `CTRL_BREAK_EVENT` требует общей консоли, а её нет. Теперь GUI пишет
  строку `STOP` в stdin воркера (флаг `--control-stdin`), воркер по ней поднимает
  `KeyboardInterrupt` — тот же путь `finally -> session.quit()`, Firefox закрывается
  штатно. Если GUI аварийно завершился (канал закрыт), воркер тоже останавливается сам.
  Если воркер не ответил за 20 с (для YouTube — 180 с, см. ниже почему), убивается всё
  дерево процессов (`taskkill /T /F`), а не только процесс-загрузчик onefile.
- **Вывод воркера.** В windowed-сборке `sys.stdout/stderr/stdin` могут быть `None`.
  `ensure_std_streams()` берёт реальные дескрипторы, унаследованные от GUI; если их
  нет — пишет журнал в `%LOCALAPPDATA%\auto_record_suno\worker-stdio.log` (GUI
  подскажет путь, если лог пуст).
- **Подпроцессы без окон.** geckodriver, ffmpeg и taskkill запускаются с
  `CREATE_NO_WINDOW` (иначе каждый открыл бы своё чёрное окно); их stdin по умолчанию
  — DEVNULL, чтобы ffmpeg не «съел» команду STOP.
- Ошибки обработчиков интерфейса и необработанное исключение воркера теперь попадают в
  лог-панель (без консоли их иначе никто бы не увидел).

При запуске из исходников (`python recorder_gui.py`) консоль терминала, из которого
вы запустили программу, остаётся — это ваш терминал.

### Перенос блока YouTube (видео) из Linux-версии

Блок YouTube перенесён «как есть» (`auto_record_youtube.py`): автообнаружение
видео, разворачивание окна Firefox и попытка полноэкранного режима, захват
области плеера, ожидание события `ended`, запись без вырезания пауз, все 7
видео-контейнеров (mp4/mkv/webm/avi/mov/flv/3gp), «звук внутри видео» с теми же
правилами совместимости и запасными вариантами (webm→Opus, flv/3gp→AAC), чистый
звук при выборе аудио-контейнера. Что заменено платформой:

| Linux | Windows |
|---|---|
| звук: `parec` (PulseAudio) | WASAPI-захват (`win_audio_loopback.py`) -> ffmpeg -> WAV 96kHz/24bit — как в Suno |
| видео: `x11grab` / `wf-recorder` | `ffmpeg -f gdigrab` (`screen_capture.py`) |
| остановка видео: SIGTERM | команда `q` в stdin ffmpeg (иначе контейнер остался бы недописанным) |
| «Стоп»: SIGINT | строка `STOP` в stdin воркера (`--control-stdin`) |
| подбор ffmpeg с libx264/libvpx | системный -> кэш -> сборка gyan.dev (`resolve_ffmpeg_bin_for_encoder`) |

Дополнительно (как у Windows-Suno): при закрытии/падении Firefox браузер
перезапускается; на «Стоп» YouTube-воркеру даётся до 180 с (Suno — 20 с) на
кодирование и сшивание, прежде чем процесс будет убит.

**DPI-масштабирование.** Координаты области плеера считаются как
`mozInnerScreenX × devicePixelRatio` (физические пиксели). Воркер вызывает
`SetProcessDPIAware()`, а ffmpeg запускается с `__COMPAT_LAYER=HIGHDPIAWARE` —
иначе при масштабе 125–150% gdigrab взял бы «виртуализированную» область.
Область дополнительно вписывается в границы виртуального экрана.

Известные особенности захвата экрана: курсор мыши попадает в кадр (как и
в Linux-версии); окно AutoRecord/другие окна поверх плеера тоже будут записаны;
защищённое DRM-видео gdigrab пишет чёрным. Если картинка окажется сдвинутой
или обрезанной при масштабе экрана 125-150% или на нескольких мониторах —
заведите Issue со строками «Область захвата экрана: ...» и «Захват видео
запущен (gdigrab ...)» из лога, а также разрешением и масштабом экрана.

## Куда сохраняются скачиваемые файлы

- **ffmpeg и geckodriver** (то, что скачивается из интернета) — в папку
  `AutoRecord-Codecs` РЯДОМ С ИСПОЛНЯЕМЫМ ФАЙЛОМ (portable-режим). Если
  туда невозможно писать (например, .exe лежит в Program Files без прав
  администратора) — используется `%LOCALAPPDATA%\auto_record_suno\codecs`
  как запасной вариант, с явным предупреждением в логе.
- Скачивание печатает источник (URL) и прогресс в процентах (шагами по
  10%) — видно как в консоли, так и в лог-панели GUI.
- **Копия профиля Firefox и путь к firefox.exe** (не скачивается, а
  берётся с этого же компьютера) — остаются в `%LOCALAPPDATA%\auto_record_suno\`,
  как и раньше.

## Сборка дистрибутива (portable .exe / .msi / Setup.exe)

`build-windows.sh` собирает готовые Windows-пакеты **без реальной
Windows-машины** (через Wine + переносимый Windows Python + PyInstaller
для самого .exe, wixl для .msi, makensis/NSIS для Setup.exe — подробности
и обоснование каждого шага см. в комментариях самого скрипта):

```bash
./build-windows.sh          # соберёт все три файла в dist-windows/
./build-windows.sh --help   # список флагов (--portable-only, --no-msi, --no-exe-installer и т.п.)
```

Результат в `dist-windows/`:
- `AutoRecord-portable.exe` — один файл, ничего не устанавливает;
- `AutoRecord-Setup.msi` — Windows Installer (удобен для silent/GPO-разворачивания);
- `AutoRecord-Setup.exe` — обычный exe-инсталлятор с привычным wizard'ом
  и записью в "Установка и удаление программ"/"Приложения и возможности".

Требует Linux (Debian/Ubuntu для автоустановки зависимостей wine/wixl/nsis).

Собранный .exe запускает и GUI (двойным щелчком), и оба воркера внутри себя
(`AutoRecord.exe --run-worker ...` для Suno, `AutoRecord.exe --run-worker-youtube ...`
для YouTube) — это делает `recorder_gui.py` автоматически, отдельно вызывать
эти флаги вручную не нужно.

## Файлы в этой поставке

- `auto_record_suno.py` — Suno-бэкенд (CLI) и общий код (Firefox, ffmpeg, захват звука)
- `auto_record_youtube.py` — YouTube-бэкенд (CLI): звук и видео
- `screen_capture.py` — захват экрана для видео (ffmpeg gdigrab, DPI, остановка по `q`)
- `recorder_gui.py` — графический интерфейс
- `win_audio_loopback.py` — захват звука WASAPI на чистом ctypes (изоляция по процессу + fallback), самодиагностика: `python win_audio_loopback.py <PID|device> [сек]`
- `win_process.py` — работа с процессами Windows
- `win_audio_devices.py` — диагностика звуковых устройств (кнопка «Проверить звуковые устройства», `--list-audio-devices`)
- `win_stdio.py` — работа без окна консоли: std-потоки, подпроцессы без окон, команда STOP через stdin
- `format_options.py`, `encode_helpers.py` — контейнеры/кодирование ffmpeg
- `i18n.py`, `gui_profiles.py` — локализация и профили GUI
- `requirements.txt` — внешних зависимостей нет (только комментарий)
- `build-windows.sh` — сборка portable .exe / .msi / Setup.exe без Windows-машины
